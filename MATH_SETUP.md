## Available resources

- Base model for this experiment: `meta-llama/Llama-3.2-1B`, already present at
  `/data/250010186/hf/Llama-3.2-1B`. Its safetensors file and tokenizer were
  checked on 2026-11-24.
- Tuning data: `meta-math/MetaMathQA`, downloaded with
  `scripts/download_hf.py` to the standard Hugging Face cache under
  `/data/250010186/hf/hub/datasets--meta-math--MetaMathQA`.
- Fixed split: `data/metamathqa_38912_train_512_val_seed42/`, generated by
  `scripts/split_metamathqa.py`. Validation has 512 distinct original questions;
  no augmentation of those questions appears in the 38,912 training rows.
- GSM8K: not downloaded, at the user's request.
- “模拟 OR” describes the experiment's intent; it is not a dataset ID.

The requested training plan is two epochs, global batch 128, sequence length
1024, with checkpoints saved for later `lm-eval` assessment. For 38,912 training
examples (the closest multiple of 128 below 39,000), this is exactly
304 optimizer steps per epoch, 608 total. On four GPUs, per-device batch 8 and
gradient accumulation 4 give global batch 128.

For batch search over 32/64/128/256, every trial must use the same 38,912
selected examples in the same tokenized form and consume each example once per
epoch. The two-epoch step counts are 2432/1216/608/304 respectively. The shared
data manifest checks the train/eval token IDs and loss masks by SHA256, records
the token count for both epochs, and rejects a trial with an incompatible step
count or incomplete global batch. Padding is excluded from this token count.

`run-llama.py` accepts `--dataset-dir` for this fixed split. The search
configurations are in `scripts/math_*.json`; `scripts/run_math_search.sh` runs
the three LR-only methods or a five-dimensional method. All methods select the
lowest final validation `eval_loss`. Model and optimizer checkpoints are
disabled; only metrics, logs, and search history are retained.
