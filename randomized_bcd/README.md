# RP-BCD / R-CD：32次训练预算

## 启动

```bash
# 1：每轮随机排列坐标
bash randomized_bcd/run.sh rp_bcd 42

# 2：每次均匀随机抽一个坐标，允许重复
bash randomized_bcd/run.sh r_cd 42
```

在4卡SCO容器内运行，仓库为`/data/250010186/SFT_code/muA-lora`。依赖安装已放进shell，使用清华源。代码已准备，尚未提交训练。

## 共同协议

- 初始LR=2^-16、warmup=0.05、beta2=0.999、global batch=32。
- 候选与当前BCD相同：LR指数18/17/16/15/14/13；warmup 0.01/0.05/0.1；beta2 0.95/0.99/0.999；batch32/64/128/256。
- **每种方法最多32个不同完整配置的训练，初始化计入预算。** 缓存命中不重复训练、不增加次数。
- 固定同一份32000条训练数据，每条使用一次；batch32/64/128/256分别对应1000/500/250/125 steps。
- 验证集32000条，每卡eval batch8，截断与loss mask一致；共享已有train/eval token SHA256校验文件。
- 搜索seed由shell第二个参数控制；训练seed仍为42，两者分开。
- 完整坐标grid扫描后，仅当eval loss下降**超过1e-5**才接受更新。
- 采用32次预算或停滞作为停止条件，**没有另外限制为2轮**。这是与目前最多2轮的固定顺序BCD的一个协议区别，比较时应注明。

## 1. RP-BCD

每轮将4个坐标随机排列，逐个扫描完整grid。前一个坐标接受的参数成为后一个坐标的基点。下一轮重新排列；一整轮没有接受更新则结束。

## 2. R-CD

每次从4个坐标中以相同概率抽一个，允许重复。抽中后扫描该坐标的完整grid。重复抽到已扫过的坐标可能全部命中缓存，此次抽样保留记录，但不消耗新的训练次数。

当前基点下4个坐标均已检查、且不能再接受更新时结束。接受一次更新会重置检查记录；刚完成的坐标自身仍标记已检查，因为其整条坐标线已评估。不因单次抽样没有改善而结束，也没有按历史收益调整抽样概率。

## 预算在grid中途耗尽

立即停止新增训练；该坐标标记`grid_complete=false`，不把部分grid结果当作一次完整坐标更新。已观测到的最低loss仍纳入最终报告。因此32次预算不会被一次grid越过。

## 输出与续跑

每个方法、每个seed都有独立目录，不读取其他方法的训练结果：

```text
checkpoints/randomized-bcd/fixed32000-budget32-20261123/
  rp_bcd/seed-42/
  r_cd/seed-42/
```

- `best.json`：最低观测loss与参数、算法接受的参数与loss、已完成训练次数、坐标访问次数、停止原因。
- `history.json`：每个不同配置的真实训练结果，按首次访问顺序记录。
- `coordinate_history.json`：每次坐标访问的基点、是否完整扫描、是否更新、新增训练次数。
- `permutations.json`：RP-BCD每轮的排列。
- `runs/<参数>/`：训练log、最终train/eval loss、trainer_state、token校验文件。不保存模型权重。

同一shell重跑会按相同搜索seed重放路径，并复用本目录的已完成结果，不重复训练。改变配置时使用新output_dir。

```bash
python randomized_bcd/test_search.py
```

测试以已知最优值的函数代替实际训练，验证选点、初始化预算、缓存、确定性续跑、随机排列、允许重复抽样、停滞条件和中途截断；训练调用复用已经验证的固定数据量入口。
